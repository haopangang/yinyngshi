## 1. 项目背景与目标

### 1.1 痛点分析

阴阳师作为网易旗舰手游，拥有庞大的日常任务体系。每日固定活动包括：

| 日常项目 | 预估耗时 | 重复频率 | 说明 |
|---------|---------|---------|------|
| 御魂副本（八岐大蛇） | 30-60 分钟 | 每日 | 刷取御魂是核心养成途径，需反复挑战 |
| 觉醒副本 | 15-30 分钟 | 每日 | 按材料类型轮换刷取 |
| 结界突破 | 10-20 分钟 | 每日 | 个人突破 + 寮突破，手动选择对手 |
| 百鬼夜行 | 10-15 分钟 | 每日 | 需持续点击撒豆，消耗大量注意力 |
| 地域鬼王 | 5-10 分钟 | 每日 | 每日 3 次挑战 |
| 签到/金币妖怪/年兽 | 5-10 分钟 | 每日 | 固定流程，纯手动领取 |
| 悬赏封印 | 5-10 分钟 | 每日 | 需识别并挑战指定妖怪 |
| 寮任务 | 5-10 分钟 | 每日 | 喂猫、结界卡操作等 |

**每日重复操作总计约 1-3 小时**，且绝大多数操作流程高度固定、无需复杂决策。

### 1.2 产品目标

构建一个**全自动托管工具**，实现：

```
定时启动 → 自动执行全日常 → 安全退出 → 无人值守运行
```

核心目标：

1. **全自动**：一键启动后无需人工干预，覆盖全部日常任务
2. **高可靠**：具备完善的异常恢复机制，网络断开、游戏崩溃、弹窗干扰均可自动处理
3. **智能化**：体力预算分配、场景状态机识别、人类行为模拟
4. **可观测**：实时状态展示 + 微信推送通知 + 每日统计报告

### 1.3 运行环境

| 项目 | 规格 |
|------|------|
| 操作系统 | macOS（Apple Silicon / Intel 均支持） |
| 设备连接 | 通过 USB / WiFi ADB 连接安卓真机 |
| ADB 版本 | Android Debug Bridge 1.0.41+ |
| 屏幕分辨率 | 支持主流分辨率（1080×2400、1440×3200 等） |
| 游戏版本 | 跟随阴阳师最新版适配 |
| 运行模式 | CLI 工具 / 守护进程 |

## 2. 功能列表与优先级

### 2.1 P0 — 必做功能

> 缺少任何一项则无法满足"全自动日常"的基本目标。

#### 2.1.1 设备管理

| 功能点 | 描述 |
|--------|------|
| 设备自动检测 | 扫描已连接的 ADB 设备列表，显示设备状态 |
| 设备连接管理 | 支持 USB / WiFi 连接，指定目标设备 |
| 游戏启动 | 通过 `am start` 启动阴阳师，等待加载完成 |
| 游戏退出 | 安全退出游戏进程 |
| 设备状态监控 | 实时检测电量、温度、连接状态 |

#### 2.1.2 御魂副本（八岐大蛇）

| 功能点 | 描述 |
|--------|------|
| 层数选择 | 支持指定第 1-10 层或悲鸣/神罚 |
| 次数控制 | 指定挑战次数，或按体力/时间自动计算 |
| 自动战斗 | 自动点击准备、自动选择阵容、自动开始 |
| 结算处理 | 自动点击结算界面，领取奖励 |
| 御魂整理 | 基础自动奉纳（P1 做高级整理） |

#### 2.1.3 觉醒副本

| 功能点 | 描述 |
|--------|------|
| 材料类型选择 | 业火轮 / 风转符 / 天雷鼓 / 镇墓兽 |
| 层数选择 | 支持第 1-10 层 |
| 自动战斗 | 同御魂副本流程 |
| 次数控制 | 指定次数或体力上限 |

#### 2.1.4 结界突破

| 功能点 | 描述 |
|--------|------|
| 个人突破 | 自动选择对手、开始战斗、结算 |
| 寮突破 | 自动进入寮突破、选择对手、战斗 |
| 刷新策略 | 突破卷用完自动刷新 |
| 失败处理 | 战斗失败自动跳过或更换对手 |

#### 2.1.5 百鬼夜行

| 功能点 | 描述 |
|--------|------|
| 自动撒豆 | 识别鬼怪位置，自动撒豆 |
| 次数管理 | 每日 5 次（免费+勾玉），可配置 |
| 基础策略 | 撒豆数量根据稀有度调整（P1 做 AI 智能版） |

#### 2.1.6 地域鬼王

| 功能点 | 描述 |
|--------|------|
| 自动挑战 | 每日 3 次挑战，自动选怪、战斗、结算 |
| 集结配置 | 可选择是否参加集结 |

#### 2.1.7 日常任务

| 任务项 | 描述 |
|--------|------|
| 每日签到 | 自动点击签到、领取奖励 |
| 金币妖怪 | 自动进入并挑战 |
| 年兽 | 自动发现并挑战（每日 2 次） |
| 悬赏封印 | 识别悬赏任务，自动挑战对应妖怪 |
| 邮件领取 | 自动领取邮件附件 |
| 寮补给 | 自动领取寮内每日补给 |

#### 2.1.8 体力管理

| 功能点 | 描述 |
|--------|------|
| 体力检测 | 实时读取当前体力值 |
| 体力预算 | 根据任务优先级分配体力 |
| 体力药使用 | 体力不足时自动使用体力药水 |
| 寿司领取 | 自动领取每日寿司体力 |
| 体力上限告警 | 体力溢出时通知用户 |

#### 2.1.9 异常恢复

| 异常类型 | 恢复策略 |
|---------|---------|
| 弹窗/广告 | 识别并关闭弹窗（公告、活动、充值等） |
| 网络断开 | 等待重连，超时后重启游戏 |
| 游戏崩溃 | 检测进程退出，自动重启游戏 |
| 设备断连 | ADB 重连，恢复后从断点继续 |
| 卡死检测 | 同一画面超时未变化，强制重启 |
| 更新提示 | 检测到版本更新时通知用户，暂停执行 |

#### 2.1.10 微信通知

| 通知渠道 | 方式 | 优势 | 劣势 |
|---------|------|------|------|
| WxPusher | 微信推送服务 | 免费、配置简单 | 依赖第三方 |
| Server酱 | SendKey 推送 | 免费、稳定 | 每日限量 |
| 企业微信机器人 | Webhook 推送 | 官方支持、稳定 | 需企业微信 |

通知场景：

- 全部日常任务完成
- 体力耗尽 / 体力溢出
- 获得稀有御魂（六星）
- 异常告警（崩溃、断连、未知弹窗）
- 每日统计报告

#### 2.1.11 定时调度

| 功能点 | 描述 |
|--------|------|
| 定时启动 | 指定时间自动启动游戏执行全日常 |
| Cron 表达式 | 支持灵活的调度时间配置 |
| 多时段调度 | 可配置多个时段（如 00:05 刷日常、12:00 领体力） |
| 工作日/周末 | 区分工作日和周末的不同执行策略 |

## 3. 用户交互设计

### 3.1 CLI 命令体系

#### 设备管理

```bash
# 列出已连接设备
yys devices

# 连接指定设备
yys connect <device-id>              # USB 设备
yys connect 192.168.1.100:5555       # WiFi ADB

# 启动 / 退出游戏
yys start [--device <id>]
yys stop  [--device <id>]

# 设备截图
yys screenshot [--output <path>]
```

#### 手动调试

```bash
# 点击坐标
yys click <x> <y>

# 滑动操作
yys swipe <x1> <y1> <x2> <y2> [duration]

# 截图并查看
yys screenshot [--open]

# 图像查找（模板匹配）
yys find <template.png>

# OCR 识别屏幕文字
yys ocr [--region <x1,y1,x2,y2>]
```

#### 任务执行

```bash
# 执行单个任务
yys run orochi [--layer 10] [--count 50]     # 御魂八岐大蛇
yys run awake  [--type fire] [--layer 8]     # 觉醒副本
yys run break  [--type personal|guild]       # 结界突破
yys run hyakki [--count 5]                   # 百鬼夜行
yys run boss   [--count 3]                   # 地域鬼王
yys run sign                                 # 签到
yys run coin                                 # 金币妖怪
yys run nian                                 # 年兽
yys run bounty                               # 悬赏封印

# 执行组合任务
yys run daily                                # 全部日常任务
yys run all                                  # 全部任务 + 御魂/觉醒

# 指定配置文件执行
yys run --config ./my-config.yaml
```

#### 调度与守护

```bash
# 启动守护进程
yys daemon start [--config <path>]
yys daemon stop
yys daemon restart
yys daemon logs [--follow]

# 定时调度
yys schedule add "0 0 5 * * *" daily         # 每天 05:00 执行日常
yys schedule add "0 30 11 * * *" all         # 每天 11:30 执行全部
yys schedule list                            # 列出所有调度
yys schedule remove <id>                     # 删除调度

# 状态查看
yys status                                   # 当前运行状态
yys report [--date today]                    # 统计报告

# 配置管理
yys config init                              # 初始化配置
yys config edit                              # 编辑配置文件
yys config show                              # 显示当前配置
```

### 3.2 配置文件（YAML）

配置文件路径：`~/.yys/config.yaml` 或项目目录下 `yys.yaml`

```yaml
# ============================================================
# 阴阳师辅助脚本配置文件
# ============================================================

# ---------- 设备配置 ----------
device:
  # 目标设备 ID（留空则自动选择第一个设备）
  id: ""
  # ADB 路径（默认使用 PATH 中的 adb）
  adb_path: "adb"
  # 截图方式: screencap | scrcpy
  screenshot_method: "screencap"
  # 屏幕分辨率（留空则自动检测）
  resolution: ""

# ---------- 游戏配置 ----------
game:
  # 阴阳师包名
  package: "com.netease.onmyoji"
  # 启动 Activity
  activity: "com.netease.onmyoji.LaunchActivity"
  # 启动等待时间（秒）
  launch_timeout: 120
  # 游戏语言
  language: "zh-CN"

# ---------- 任务配置 ----------
tasks:
  # --- 御魂副本 ---
  orochi:
    enabled: true
    layer: 10                  # 层数：1-10, 11=悲鸣, 12=神罚
    count: 30                  # 挑战次数（0=不限）
    stamina_limit: 300         # 本次最多消耗体力
    team_preset: 1             # 阵容预设编号

  # --- 觉醒副本 ---
  awake:
    enabled: true
    type: "fire"               # fire / wind / thunder / tomb
    layer: 8
    count: 20
    stamina_limit: 200

  # --- 结界突破 ---
  breakthrough:
    enabled: true
    personal: true             # 个人突破
    guild: true                # 寮突破
    refresh_on_empty: true     # 突破卷用完自动刷新
    max_defeats: 3             # 连败次数上限，超过则跳过

  # --- 百鬼夜行 ---
  hyakki:
    enabled: true
    count: 5                   # 次数（含勾玉购买）
    buy_with_jade: true        # 使用勾玉购买额外次数
    bean_strategy: "normal"    # normal / aggressive / ssr_focus

  # --- 地域鬼王 ---
  region_boss:
    enabled: true
    count: 3
    join_assembly: false       # 是否参加集结

  # --- 日常杂项 ---
  daily:
    sign_in: true              # 签到
    coin_monster: true         # 金币妖怪
    nian_beast: true           # 年兽
    bounty_seal: true          # 悬赏封印
    mail: true                 # 领取邮件
    guild_supply: true         # 寮补给

  # --- 寮任务 ---
  guild:
    enabled: false             # P1 功能，默认关闭
    feed_cat: true
    card_combine: true
    card_set: true
    card_collect: true

# ---------- 体力管理 ----------
stamina:
  # 体力药水使用策略
  auto_use_potion: true        # 体力不足时自动使用
  potion_reserve: 3            # 保留体力药数量
  # 体力预算（每日总消耗上限）
  daily_budget: 800
  # 体力分配优先级（数字越小优先级越高）
  priority:
    orochi: 1                  # 御魂优先
    awake: 2
    breakthrough: 3
  # 体力溢出告警阈值
  overflow_alert: 900

# ---------- 异常恢复 ----------
recovery:
  # 弹窗自动关闭
  auto_close_popup: true
  # 网络重连超时（秒）
  reconnect_timeout: 60
  # 崩溃重启等待（秒）
  crash_restart_delay: 15
  # 卡死检测超时（秒）——同画面无变化判定为卡死
  stuck_timeout: 30
  # 最大重启次数（超过则停止并通知）
  max_restarts: 5

# ---------- 通知配置 ----------
notification:
  # WxPusher
  wxpusher:
    enabled: false
    app_token: ""
    uids: []

  # Server酱
  server_chan:
    enabled: false
    send_key: ""

  # 企业微信机器人
  wecom:
    enabled: false
    webhook_url: ""
    secret: ""

  # 通知场景开关
  scenes:
    daily_complete: true       # 日常完成
    stamina_exhausted: true    # 体力耗尽
    stamina_overflow: true     # 体力溢出
    rare_drop: true            # 稀有掉落（六星御魂）
    error_alert: true          # 异常告警
    daily_report: true         # 每日报告

# ---------- 定时调度 ----------
schedule:
  # Cron 表达式：秒 分 时 日 月 周
  jobs:
    - name: "morning_daily"
      cron: "0 0 5 * * *"      # 每天 05:00
      task: "daily"
      enabled: true

    - name: "noon_stamina"
      cron: "0 30 11 * * *"    # 每天 11:30
      task: "collect_stamina"
      enabled: true

    - name: "evening_orochi"
      cron: "0 0 21 * * *"     # 每天 21:00
      task: "orochi"
      enabled: true
      params:
        layer: 10
        count: 50

# ---------- 人类行为模拟 ----------
humanize:
  enabled: true
  # 点击延迟范围（毫秒）
  tap_delay: [100, 500]
  # 滑动延迟范围（毫秒）
  swipe_delay: [200, 800]
  # 操作间隔范围（毫秒）
  action_interval: [500, 2000]
  # 贝塞尔曲线偏移（像素）
  bezier_offset: 30
  # 随机抖动（像素）
  random_jitter: 5

# ---------- 守护进程 ----------
daemon:
  # 日志路径
  log_dir: "~/.yys/logs"
  # 日志保留天数
  log_retention: 7
  # PID 文件
```

### 4.2 体力预算与分配

体力是有限的核心资源，需要智能分配以最大化收益。

**分配策略**：

```
总可用体力 = 当前体力 + 体力药恢复量 - 安全保留量

按优先级依次分配：
  1. 御魂副本（优先级最高，消耗体力最多）
  2. 觉醒副本
  3. 结界突破（消耗突破卷，不消耗体力）

每个任务设置体力上限，防止单任务耗尽所有体力
```

**预算计算示例**：

```
假设当前体力: 600, 每日预算: 800, 体力药×5（每个恢复100）

可用体力 = 600 + 500 - 100（保留） = 1000

分配:
  御魂: min(30次×8体力, 1000×0.5) = 240 体力 → 30次
  觉醒: min(20次×6体力, 剩余×0.6) = 120 体力 → 20次
  剩余: 1000 - 240 - 120 = 640 体力 → 溢出告警
```

### 4.3 异常检测与自动恢复

采用**分层异常处理**策略：

| 层级 | 异常类型 | 检测方式 | 恢复动作 | 超时 |
|------|---------|---------|---------|------|
| L1 | 弹窗/公告 | 模板匹配检测到非预期界面 | 点击关闭按钮 | 3秒 |
| L2 | 网络断开 | 检测重连弹窗 / logcat 日志 | 等待重连 → 超时重启游戏 | 60秒 |
| L3 | 游戏崩溃 | ADB 检测进程不存在 | 重启游戏，从断点继续 | 120秒 |
| L4 | 设备断连 | ADB 连接丢失 | `adb reconnect` → 重启ADB | 30秒 |
| L5 | 画面卡死 | 连续 N 帧截图无差异 | 强制重启游戏 | 30秒 |
| L6 | 未知状态 | 无法匹配任何已知场景 | 截图保存 + 通知用户 + 重试 | 10秒 |

**恢复流程**：

```
异常发生
  │
  ├─ L1 弹窗 → 尝试关闭 → 成功 → 继续
  │                         失败 → 升级
  │
  ├─ L2 网络 → 等待30s → 重连成功 → 继续
  │                     重连失败 → 重启游戏
  │
  ├─ L3 崩溃 → 重启游戏 → 等待加载 → 从断点继续
  │
  ├─ L4 断连 → adb reconnect → 成功 → 重启游戏继续
  │                            失败 → 通知用户
  │
  └─ 重启次数 > max_restarts → 停止所有任务 → 发送告警
```

### 4.4 人类行为模拟

为降低被游戏反作弊系统检测的风险，所有操作模拟人类行为特征：

#### 点击模拟

```python
def human_tap(target_x, target_y):
    # 1. 随机偏移（模拟手指不精确）
    offset_x = random.gauss(0, config.humanize.random_jitter)
    offset_y = random.gauss(0, config.humanize.random_jitter)
    x = target_x + offset_x
    y = target_y + offset_y

    # 2. 随机延迟（模拟反应时间）
    delay = random.uniform(*config.humanize.tap_delay)
    sleep(delay / 1000)

    # 3. 执行点击
    adb.input_tap(x, y)
```

#### 滑动模拟（贝塞尔曲线）

```python
def human_swipe(x1, y1, x2, y2):
    # 生成贝塞尔曲线路径点
    control_1 = (
        x1 + (x2 - x1) * 0.3 + random_offset(),
        y1 + (y2 - y1) * 0.1 + random_offset()
    )
    control_2 = (
        x1 + (x2 - x1) * 0.7 + random_offset(),
        y1 + (y2 - y1) * 0.9 + random_offset()
    )

    points = bezier_curve(
        start=(x1, y1),
        cp1=control_1,
        cp2=control_2,
        end=(x2, y2),
        steps=random.randint(20, 40)
    )

    # 沿曲线逐步滑动，速度先快后慢
    for i, (px, py) in enumerate(points):
        adb.input_move(px, py)
        # 模拟加速→减速
        progress = i / len(points)
        speed_factor = 1.0 - 0.5 * math.sin(progress * math.pi)
        sleep(base_interval * speed_factor)
```

#### 行为特征

| 特征 | 模拟方式 | 参数 |
|------|---------|------|
| 点击偏移 | 高斯分布随机偏移 | σ = 5px |
| 反应延迟 | 均匀分布随机等待 | 100-500ms |
| 操作间隔 | 正态分布间隔 | μ=1200ms, σ=300ms |
| 滑动轨迹 | 三阶贝塞尔曲线 | 20-40个路径点 |
| 滑动速度 | 先加速后减速 | 正弦速度曲线 |
| 偶尔"失误" | 极低概率误点后立即返回 | 0.5% 概率 |

## 6. 技术约束与非功能性需求

### 6.1 性能要求

| 指标 | 要求 |
|------|------|

### 6.2 稳定性要求

| 指标 | 要求 |
|------|------|
| 单次运行时长 | ≥ 3 小时无故障 |
| 异常恢复成功率 | ≥ 95% |
| 场景识别准确率 | ≥ 99% |
| 误操作率 | ≤ 0.1% |

- 所有操作模拟人类行为，不使用内存注入/Hook 等侵入式技术
- 配置文件中的 Token/Key 加密存储

- 遵循游戏使用条款，仅辅助自动化操作

- 任务系统采用插件化设计，新增日常任务只需实现任务接口
- 模板图片按版本管理，游戏更新时只需替换模板
