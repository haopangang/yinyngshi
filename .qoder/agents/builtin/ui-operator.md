# 阴阳师辅助脚本 - UI 操作规范

## 概述

本 agent 负责定义阴阳师游戏内 UI 操作的自动化规范，包括坐标系统、操作流程、状态判定等。

## 坐标系与分辨率

- 基准分辨率：1080x1920（竖屏）或 1920x1080（横屏）
- 所有坐标和模板图片基于基准分辨率制作
- 运行时根据实际分辨率自动缩放
- 坐标表示：`(x, y)` 为像素坐标，`[x1, y1, x2, y2]` 为矩形区域

## 游戏界面导航

### 主界面（町中）
- 作为所有任务的起点和终点
- 关键元素：探索灯笼、御魂入口、觉醒入口、结界入口
- 导航逻辑：任何任务完成后必须回到主界面

### 常用导航路径
```
主界面 -> 探索 -> 御魂 -> 八岐大蛇
主界面 -> 探索 -> 御魂 -> 业原火
主界面 -> 探索 -> 觉醒 -> 各层
主界面 -> 结界 -> 结界突破
主界面 -> 召唤 -> 抽卡界面
```

### 导航实现规范
- 使用模板匹配确认当前界面，而非依赖坐标点击
- 每次导航后必须验证是否到达目标界面
- 导航失败时应有重试机制（最多 3 次）
- 遇到意外弹窗应优先关闭再继续导航

## 操作流程规范

### 点击操作
- 点击后等待界面响应（至少 0.5s）
- 关键按钮点击后需验证状态变化
- 避免快速连续点击（模拟人类操作节奏）
- 点击坐标添加随机偏移（±5px）避免被检测

### 滑动操作
- 滑动速度：300-500ms
- 滑动后等待惯性结束
- 长列表滑动需要分段进行

### 等待操作
- 所有等待必须设置超时
- 战斗结束检测：检测"胜利"或"失败"界面
- 加载界面检测：检测加载动画消失
- 默认超时：30s（战斗等待可延长到 300s）

## 状态检测

### 场景识别
- 使用模板匹配识别当前场景
- 每个场景有唯一标识（如 `scene_main`, `scene_battle`, `scene_dungeon`）
- 场景识别结果缓存，避免重复计算

### 弹窗处理
- 优先级：公告弹窗 > 活动弹窗 > 奖励弹窗
- 弹窗检测使用多模板匹配（一次检测多种弹窗类型）
- 关闭弹窗后等待界面稳定（1s）

### 资源状态
- 体力值：OCR 读取左上角体力数字
- 勾玉数量：OCR 读取
- 金币数量：OCR 读取
- 读取失败时使用保守策略（假设资源不足）

## 异常恢复

### 卡死检测
- 连续 N 次截图相似度 > 99% 判定为卡死
- 卡死后执行：返回主界面 -> 重新尝试任务
- 连续 3 次卡死恢复失败则通知用户

### 闪退处理
- 检测游戏进程是否存活
- 闪退后重启游戏 -> 等待加载 -> 回到主界面
- 检查任务进度，决定是否继续或跳过

### 网络断开
- 检测网络错误弹窗
- 等待网络恢复 -> 重新登录
- 超时后通知用户

## 模板图片管理

### 命名规范
```
assets/templates/
├── navigation/         # 导航相关（主界面按钮等）
├── battle/             # 战斗相关（开始、结束、胜利等）
├── dungeon/            # 副本相关
│   ├── orochi/         # 御魂
│   └── awakening/      # 觉醒
├── popup/              # 弹窗关闭按钮
└── common/             # 通用元素（确认、取消等）
```

### 制作规范
- 格式：PNG（无损压缩）
- 截取时确保元素完整，边缘留 2-3px 余量
- 避免包含动态内容（数字、动画）
- 每个模板图片附带 `meta.yaml` 描述用途和截取条件
