# 阴阳师辅助脚本 - 研究指导

## 研究范围

### 游戏机制
- 阴阳师游戏核心玩法：御魂副本、觉醒副本、探索副本、斗技、结界突破等
- 体力系统、勾玉系统、式神系统、御魂系统的运作逻辑
- 日常任务清单与奖励机制
- 游戏内各界面的操作流程和跳转逻辑
- 活动时间表和限时活动机制

### 技术参考项目
- **OAS (Onmyoji Auto Script)**：成熟的阴阳师自动化开源项目，重点研究其：
  - 任务架构设计（任务注册、生命周期管理）
  - 场景识别方案（基于图像特征的场景判定）
  - 异常恢复机制（卡死检测、战斗失败处理）
  - 配置管理方案
  - 设备适配策略
- 其他相关开源项目：onmyoji-bot、yys-auto 等

### 核心技术调研

#### ADB 设备控制
- uiautomator2 的 API 和最佳实践
- 屏幕截图获取方案（scrcpy、minicap、adb screencap）
- 触摸事件模拟（tap、swipe、长按）
- 多设备管理

#### 图像识别
- OpenCV 模板匹配算法（TM_CCOEFF_NORMED 等）
- 多尺度匹配策略
- 场景特征提取与分类
- 游戏画面中的 UI 元素定位

#### OCR 文字识别
- PaddleOCR / ppocr-onnx 的使用与优化
- 游戏内数字识别（体力值、金币、勾玉数量）
- 中文文字识别（式神名称、御魂属性）
- ROI 区域裁剪提升识别速度

#### 调度策略
- APScheduler 的 cron/interval 调度
- 体力恢复计算与定时唤醒
- 任务优先级排序算法
- 活动时间窗口管理

### 异常处理研究
- 游戏闪退/卡死检测方案
- 网络断开重连处理
- 弹窗检测与关闭策略（活动弹窗、公告弹窗）
- 战斗失败场景的恢复逻辑
- 设备断连自动重连

### 性能优化方向
- 截图到识别的端到端延迟优化
- 模板图片的预处理与缓存策略
- 减少不必要的截图次数
- OCR 识别的批处理优化

## 研究方法
- 优先查阅 OAS 项目的源码和文档
- 参考阴阳师官方公告了解游戏机制变化
- 在社区（NGA、贴吧、GitHub Issues）中收集实际用户场景
- 对技术方案进行可行性评估，输出结论和建议

## 竞品分析

### OAS (Onmyoji Auto Script)
- GitHub: https://github.com/runhey/OnmyojiAutoScript
- 基于 Alas（碧蓝航线脚本）魔改，重度使用图像识别
- 支持多账号、多设备
- 优点：功能全面、社区活跃、文档完善
- 缺点：代码复杂度高、配置门槛高
- 值得借鉴：任务注册机制、场景状态机、设备管理器抽象

### yys-auto 系列
- 轻量级方案，通常基于 ADB + 简单图像匹配
- 适合单一任务自动化
- 值得借鉴：简洁的配置方案
